Tailwind CSS v4 테마 시스템 파헤치기

globals.css 의 @theme 가 어떻게 bg-surface-strong 같은 유틸리티를 만들어내는지, 그리고 다크 모드·디자인 토큰 계층까지 — 이번 세션에서 다룬 내용을 정리했습니다.

목차

  1. 유틸리티 클래스는 어디서 정의되나
  2. --surface-strong → bg-surface-strong 3단계
  3. @theme 문법
  4. inline 이 막는 것 — :root 내보내기

1유틸리티 클래스는 어디서 정의되나

bg-surface-strong 같은 커스텀 유틸리티는 별도 config 파일이 아니라 Tailwind v4 방식대로 CSS 안, 즉 src/app/globals.css 한 곳에서 만들어집니다. 핵심은 @theme 블록입니다.

동작은 세 곳으로 나뉩니다:

역할위치 (globals.css)내용
원본 색 값:root / .dark--surface-strong: #f2f2f2;
유틸리티 생성@theme inline--color-surface-strong: var(--surface-strong);
실제 사용컴포넌트 className<div class="bg-surface-strong">
KEY

Tailwind v4 는 @theme 안의 --color-* 변수를 스캔해서 bg-*, text-*, border-* 유틸리티를 자동 생성합니다.

2--surface-strong → bg-surface-strong 3단계

① 순수 색 값 선언

:root {
  --surface-strong: #f2f2f2;   /* globals.css:37 */
}
.dark {
  --surface-strong: #f2f2f2;   /* 다크모드용 재정의 */
}

여기까지는 그냥 CSS 변수입니다. 이 상태로는 Tailwind 가 모르므로 bg-surface-strong 은 아직 존재하지 않습니다.

② @theme 에 색상 토큰으로 등록 (핵심)

@theme inline {
  --color-surface-strong: var(--surface-strong);   /* 이 줄이 유틸리티를 만든다 */
}

접두어 --color- 를 떼고 남은 이름 surface-strong 이 색상 팔레트 항목으로 등록되고, 그에 대한 색 계열 유틸리티가 자동으로 딸려 나옵니다.

③ 최종 참조 체인

유틸리티
bg-surface-strong
→
@theme 매핑
var(--surface-strong)
→
:root 값
#f2f2f2

같은 이름으로 text-surface-strong, border-surface-strong 등도 함께 사용 가능해집니다.

3@theme 문법

@theme 는 Tailwind v4 에서 도입된 at-rule 로, v3 의 tailwind.config.js 의 theme: {} 를 CSS 안으로 옮겨온 것입니다. 블록 안 변수는 정해진 네임스페이스 접두어로 시작해야 하고, 그 접두어가 어떤 종류의 유틸리티를 만들지 결정합니다.

접두어등록 대상생성 유틸리티
--color-*색상 팔레트bg-*, text-*, border-*, ring-*…
--font-*폰트 패밀리font-*
--spacing-*간격p-*, m-*, gap-*
--radius-*모서리 반경rounded-*
--shadow-*그림자shadow-*
--text-*타이포그래피text-* (크기+행간+굵기)
--breakpoint-*반응형sm:, md:… 변형

그래서 이 프로젝트의 --radius-sm/md/lg 는 rounded-sm/md/lg 를, --text-display-xl 등은 그 이름의 텍스트 유틸리티를 만듭니다.

KEY

@theme 는 유틸리티 생성 더하기, 등록한 변수를 실제 :root CSS 변수로도 내보냅니다. → 유틸리티를 안 써도 var(--color-...) 로 직접 참조 가능. 바로 이 "내보내기"를 inline 이 끕니다. (다음 절)

4inline 이 막는 것 — :root 내보내기

inline 은 옵션 수식어로, "토큰 변수를 :root 에 내보내지 말고 그 값을 유틸리티에 직접 박아라"는 뜻입니다. 막는 것은 딱 하나 — --color-* 변수의 내보내기입니다.

@theme (inline 없음)

:root {
  --color-surface-strong: var(--surface-strong);
}
.bg-surface-strong {
  background-color: var(--color-surface-strong);
}

--color-surface-strong 이 :root에 존재 → var()로 접근 가능하지만 이중 참조.

@theme inline

/* --color-* 는 내보내지 않음 */
.bg-surface-strong {
  background-color: var(--surface-strong);
}

var(--color-surface-strong) 는 존재하지 않음. 유틸리티가 원본을 직접 참조.

변수@theme@theme inline
--surface-strong (:root에 직접 선언한 원본)존재 ✅존재 ✅
--color-surface-strong (@theme이 만든 토큰):root에 내보냄 ✅안 내보냄 ❌
.bg-surface-strong 참조var(--color-surface-strong)var(--surface-strong)
왜 막나

토큰 변수를 중간에 끼우지 않고 유틸리티가 원본 --surface-strong 을 곧바로 가리키게 하려는 것. 그래야 .dark { --surface-strong: ... } 로 원본만 바꿨을 때 색이 정확히 따라옵니다. (중간의 --color-surface-strong 이 :root에 한 번 고정 평가되는 것을 피함.)

5inline 없이 다크 테마 + 이중 var() 회피

세 조건을 동시에 원할 때 — ① 이중 var() 회피, ② 다크 전환 동작, ③ inline 미사용(--color-* 를 :root에 남김) — 해법은 변수를 두 겹으로 나누지 말고 하나로 합치는 것입니다.

원인: 변수가 2단이라 이중 var() 발생

:root         { --surface-strong: #f2f2f2; }                 /* 원본 */
@theme inline { --color-surface-strong: var(--surface-strong); } /* 토큰이 원본 참조 */

inline 을 빼면 이 2단이 그대로 :root에 박혀 var(var()) 간접 참조가 됩니다. 근원은 inline이 아니라 변수가 두 겹이라는 사실.

해법: 값을 @theme 에 직접 넣고 .dark 에서 같은 변수를 덮어쓰기

@theme {
  --color-surface-strong: #f2f2f2;   /* 라이트 기본값 (var 아님) */
}

.dark {
  --color-surface-strong: #1a1a1a;   /* 같은 변수를 다크 스코프에서 재정의 */
}

생성 결과는 .bg-surface-strong { background-color: var(--color-surface-strong) } 한 겹뿐. CSS 변수는 사용 지점 스코프에서 평가되므로, .dark 안 요소는 자동으로 #1a1a1a 로 해석됩니다.

✔ 세 조건 모두 충족

이중 var 없음 (한 겹 참조) · 다크 동작 (스코프 재정의) · inline 불필요 (--color-* 가 :root에 남아 JS·arbitrary value 접근 가능).

트레이드오프

변수를 1단으로 합치면 여러 시맨틱 역할이 같은 팔레트 색을 공유하던 연결이 끊깁니다. → 다음 절의 "2계층" 이점을 포기하게 됩니다. 상황에 맞게 선택.

6팔레트 / 시맨틱 2계층

색 변수에는 성격이 다른 두 종류의 이름이 있습니다.

① 팔레트 (무슨 색인가)

--surface-strong: #f2f2f2; /* 연한 회색 강 */
--surface-soft:   #f7f7f7; /* 연한 회색 약 */
--primary:        #3d5af0; /* 코발트 블루 */

② 시맨틱 (어디에 쓰는 색인가)

--accent:    var(--surface-strong); /* 강조 배경 */
--secondary: var(--surface-soft);   /* 보조 배경 */
--muted:     var(--surface-soft);   /* 음소거 배경 */

--accent, --secondary, --muted 는 서로 다른 역할이지만 실제로는 같은 팔레트 색을 공유합니다. 팔레트를 진실의 원천(single source of truth) 으로 두면 팔레트 한 곳만 바꿔도 그 색을 쓰는 모든 역할이 함께 바뀝니다.

현재 프로젝트는 "반쪽짜리" 2계층

지금 globals.css 는 --secondary: #f7f7f7 와 --surface-soft: #f7f7f7 를 각각 리터럴로 중복 기입하고 주석으로만 연결을 표시합니다. 코드상 두 값은 따로 노는 상태 — var() 로 연결해야 완전한 2계층이 됩니다.

완전한 2계층의 이점 (특히 다크 모드)

시맨틱이 팔레트를 참조하면, .dark 가 시맨틱 ~30개를 복붙할 필요 없이 팔레트만 오버라이드하면 됩니다. 시맨틱은 자동으로 따라옵니다.

요약

팔레트 = "무슨 색"(원본) · 시맨틱 = "어디에 쓰는 색"(역할, 팔레트 참조) · @theme = 둘을 유틸리티로 노출. 관리 편의(한 곳에서 색 제어) ↔ 구조 단순함의 트레이드오프.

이번 세션 핵심 3줄

TL;DR

1. @theme 의 --color-* 가 bg-*/text-*/border-* 유틸리티를 자동 생성한다.

2. inline 은 --color-* 의 :root 내보내기를 끄고 값을 유틸리티에 직접 박아, 원본 변수 기반 다크 전환을 정확하게 만든다.

3. 팔레트(원본)와 시맨틱(역할)을 var() 로 연결하면 색을 한 곳에서 관리하고 다크 모드 정의가 팔레트 오버라이드만으로 끝난다.
